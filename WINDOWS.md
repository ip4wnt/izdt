# IZDT: запуск из Git на Windows

Единственный источник кода и данных: репозиторий [ip4wnt/izdt](https://github.com/ip4wnt/izdt), ветка `main`. Сервис работает прямо из локального клона; отдельная версия в ZIP больше не используется.

## Первый запуск

Установите Git for Windows и Node.js 22.12 или новее. Node.js доступен на [официальной странице загрузки](https://nodejs.org/en/download); оставьте включённой установку npm и добавление в PATH.

В PowerShell:

```powershell
git clone https://github.com/ip4wnt/izdt.git C:\izdt
cd C:\izdt
.\START-IZDT.cmd
```

Лаунчер установит зависимости, соберёт редактор и откроет `http://127.0.0.1:3000`. Вместо двойного щелчка также можно использовать `npm.cmd run local`. Права администратора для самого IZDT не нужны; папка должна быть доступна для записи.

Оставляйте окно сервера открытым во время работы. Для остановки сохраните правки через `Ctrl+S`, дождитесь статуса «Сохранено», затем нажмите `Ctrl+C` в окне сервера.

## Если уже работали в старом ZIP-комплекте

Не стирайте старую папку: в ней находятся ваши правки книги. Сначала сохраните их и остановите старый сервер.

1. Сделайте резервную копию старой папки.
2. Если она называется `C:\izdt`, переименуйте её в `C:\izdt-old`.
3. Клонируйте репозиторий в `C:\izdt`, как показано выше.
4. Скопируйте содержимое старой `data` поверх новой `data`, а старой `public\fonts` поверх новой `public\fonts`. Код и `node_modules` из старой папки не переносите.

Пример команд при указанных именах папок:

```powershell
Copy-Item -Path C:\izdt-old\data\* -Destination C:\izdt\data -Recurse -Force
Copy-Item -Path C:\izdt-old\public\fonts\* -Destination C:\izdt\public\fonts -Recurse -Force
cd C:\izdt
git status --short
git add data/books/bees
git diff --cached --stat
git commit -m "Import my local book and notes"
git push origin main
.\START-IZDT.cmd
```

Проверьте пути и список изменений до коммита. Для `git push` нужна авторизация в вашем GitHub-аккаунте; пароль или токен в файлы проекта записывать не нужно.

Если Git попросит имя и email автора, задайте их для этого репозитория командами `git config user.name "Ваше имя"` и `git config user.email "Ваш email для коммитов"`, затем повторите коммит. При желании используйте noreply-адрес из настроек вашего GitHub, чтобы не раскрывать личный email.

Текущие правки на вашем компьютере не появятся в GitHub сами по себе. Их необходимо перенести и отправить по этим шагам; агент не получает содержимое вашей локальной папки автоматически.

## Обычный рабочий цикл

Перед работой, при остановленном сервере и отсутствии несохранённых изменений Git:

```powershell
cd C:\izdt
git pull --ff-only origin main
.\START-IZDT.cmd
```

После работы: сохраните книгу, остановите сервер и отправьте данные:

```powershell
git status --short
git add data/books/bees
git diff --cached --stat
git commit -m "Update book and notes"
git push origin main
```

Если изменений нет, коммит не нужен. Если на GitHub уже появились новые коммиты и push отклонён, сначала сохраните собственные изменения коммитом, затем:

```powershell
git pull --rebase origin main
git push origin main
```

При конфликте остановитесь и разберите его вручную; не используйте `push --force`, `reset --hard` или перезапись всей папки. Git не является системой совместного редактирования в реальном времени: два компьютера не должны одновременно править одну книгу без согласования.

Ни лаунчер, ни автосохранение не запускают `git commit` или `git push`. Автосохранение пишет файлы на диск; команды Git осознанно отправляют эти файлы в репозиторий.

## Какие данные синхронизируются

| Файл или папка | Назначение |
|---|---|
| `data/books/bees/content.html` | Текст, стили, положение и обтекание картинок |
| `meta.json` | Название и ревизия |
| `toc.json`, `toc-overrides.json` | Оглавление и ручные правки |
| `img/` | Иллюстрации, в том числе новые загрузки |
| `notes.json` | Общие заметки локальной книги |
| `bookmark.json` | Общая закладка |
| `readers/<uuid>/notes.json` | Заметки из первой версии, автоматически подхватываются |

Пути в таблице после первой строки относятся к той же папке `data/books/bees`. В локальном режиме заметки и закладка общие для браузеров, работающих с этой копией книги; разные машины получают обновления после commit/push/pull.

Старые заметки объединяются по ID с `notes.json`, исходные файлы не удаляются. Старая браузерная закладка переносится при первом открытии в прежнем браузере, если общая закладка ещё не установлена.

Репозиторий публичный: владелец явно разрешил публикацию текста, иллюстраций и заметок. Проверяйте новые загружаемые файлы перед отправкой, если они могут содержать чужие персональные данные.

Не синхронизируются `node_modules`, `dist`, сгенерированные HTML-копии, локальные autosave-снимки в `history`, тестовые файлы и шрифты. История Git хранит отправленные версии; `history` служит отдельной локальной страховкой между коммитами.

## Шрифты

Из-за лицензионных ограничений шрифты остаются локальным исключением. Скопируйте уже присланные файлы из старой версии в `public\fonts`, сохранив имена:

- `marxiana.ttf`
- `marxiana-italic.ttf`
- `akzidenz-boldcn.ttf`

`git pull` их не удаляет, `.gitignore` не даёт случайно добавить их обычным `git add`. TT Marxiana Trial предназначен для тестирования; для полноценного использования нужны соответствующие лицензии.

## Редактор

- `E` / `У`: включить редактор; `Esc`: сохранить и выйти.
- Стиль на панели меняется вместе с курсором. «Разные стили» означает выделение с разным форматированием.
- Стиль применяется к затронутым абзацам и сбрасывает ручные размер/гарнитуру, чтобы действительно соответствовать выбранному стилю.
- Гарнитура и размер применяются к выделенному тексту; без выделения задают формат последующего ввода. Для всего абзаца сначала выделите его.
- Интерлиньяж, красная строка и выравнивание применяются к затронутым абзацам. Значения типографики указаны в rem, как в исходном макете; обычный текст: `2.05rem`.
- Нажмите картинку: доступны обтекание, положение, ширина, описание и удаление. Ширину также можно менять нижним правым маркером.
- «Вокруг рамки»: картинка слева или справа, текст обтекает её. «Сверху и снизу»: отдельная строка с выравниванием. «В строке»: картинка внутри текстовой строки.
- Гравюра титула сохраняет исходную композицию. Кнопка «Обычная картинка» превращает титул в обычные редактируемые блоки; действие можно отменить.
- `Ctrl+Z`, `Ctrl+Y` / `Ctrl+Shift+Z`: отмена и повтор, включая стили и изображения.

Это редактор книги с привычными текстовыми операциями, а не полная копия Word. Разбивки на печатные страницы, импорта DOCX и совместного онлайн-редактирования пока нет.

## Локальная безопасность и проверка Windows

Лаунчер включает редактор без пароля, слушает только `127.0.0.1` и отклоняет посторонние Origin/Host. Порты в роутере, публичные туннели и разрешение входящего доступа из внешней сети не нужны.

Если порт 3000 занят, закройте старый сервер. Для осознанного выбора другого порта используйте `$env:IZDT_PORT = "3001"` перед запуском.

Сборка, сервер и браузерные сценарии проверяются в Linux с Node.js 22. Ветка `cmd.exe`, двойной щелчок и автоматическое открытие браузера требуют окончательной проверки на вашем Windows-компьютере.
