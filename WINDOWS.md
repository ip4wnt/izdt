# IZDT: локальный запуск в Windows

Это локальная тестовая версия: редактор, книга и изображения работают на вашем компьютере. Публиковать её в интернете или открывать порт в роутере не нужно.

## Первый запуск

1. Установите Node.js версии 22.12 или новее с [официальной страницы загрузки](https://nodejs.org/en/download). Для Windows выбирайте установщик и LTS-ветку; оставьте включённой установку npm и добавление в PATH.
2. Распакуйте весь архив, например в `C:\izdt`. Не запускайте файл прямо из окна ZIP. Нужна обычная папка с правом записи, не `Program Files`; для рабочей копии лучше не использовать папку синхронизации OneDrive.
3. Дважды нажмите `START-IZDT.cmd`.
4. При первом запуске нужен интернет для установки зависимостей. После сборки браузер откроется автоматически по адресу `http://127.0.0.1:3000`.

Git, Docker, Python и отдельная база данных для этого способа не нужны. Права администратора для самого IZDT не требуются.

Если браузер не открылся, вручную введите указанный локальный адрес. Если Node.js установлен, но запуск сообщает об обратном, закройте окно запуска, выйдите из старого терминала и запустите файл заново.

## Работа и остановка

- Оставляйте окно `IZDT - local server` открытым, пока работаете.
- `E` / `У` включает редактор. `Ctrl+S` сохраняет, `Esc` сохраняет и выходит из редактора.
- `C` / `С` открывает оглавление, `B` / `И` открывает заметки.
- Перед остановкой нажмите `Ctrl+S` и дождитесь сообщения о сохранении. Затем нажмите `Ctrl+C` в окне сервера; если Windows спросит о завершении пакетного файла, подтвердите.
- Для следующего запуска снова откройте `START-IZDT.cmd`. Неизменившиеся зависимости повторно не устанавливаются; интернет при обычном повторном запуске не нужен.

Не запускайте две копии сервиса одновременно на одной папке книги. Если порт 3000 занят, сначала закройте прежнее окно IZDT. Для осознанного выбора другого порта можно выполнить в PowerShell из папки проекта:

```powershell
$env:IZDT_PORT = "3001"
.\START-IZDT.cmd
```

Порт является частью адреса браузера. При его смене, переходе с `127.0.0.1` на `localhost`, смене браузера или профиля вы получите отдельные идентификатор читателя и закладку.

## Где ваши данные

Книга, иллюстрации, история правок и файлы заметок находятся в `data\books\bees`. Для резервной копии остановите сервер и скопируйте всю папку `data` в другое место.

Идентификатор читателя и текущая закладка хранятся отдельно в браузере, в localStorage. Резервная копия `data` сохраняет сами заметки, но не восстанавливает автоматически их привязку после очистки данных браузера. Не очищайте данные сайта и не используйте режим инкогнито для постоянной работы.

Перед обновлением всегда делайте резервную копию `data`. Не распаковывайте новую версию поверх рабочей папки без проверки: демонстрационные файлы книги из архива могут затереть ваши правки. Автоматическое безопасное обновление в этой версии не реализовано.

## Шрифты

Локальный комплект содержит присланные вами шрифты для проверки макета; в публичном GitHub их нет. TT Marxiana Trial допускает тестирование, но не использование в личных или коммерческих проектах по метаданным файлов, поэтому этот комплект предназначен для локального тестирования, а не для постоянного использования или распространения.

Для полноценной эксплуатации замените файлы в `public\fonts` лицензированными шрифтами с соответствующим разрешением. Сохраните имена `marxiana.ttf`, `marxiana-italic.ttf`, `akzidenz-boldcn.ttf`; подробнее в `public\fonts\README.md`.

## Безопасность и ограничения

Локальный запуск включает редактор без пароля, принудительно слушает только `127.0.0.1` и отклоняет запросы с посторонними Origin/Host. Это не авторизация пользователей: другие процессы или пользователи того же компьютера потенциально могут обращаться к локальному сервису.

Не включайте доступ из интернета, туннели и перенаправление портов для этого режима. Firewall-исключение для публичной сети не нужно. Автозапуска при входе в Windows нет: приложение работает только пока открыт сервер.

Нативная Windows-среда в ходе подготовки комплекта недоступна. Сервер, сборка, проверки API и логика запуска проверяются в Linux с Node.js 22; работу `cmd.exe` и автоматическое открытие браузера необходимо подтвердить на вашем компьютере.
