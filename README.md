# IZDT

Редактор электронных книг и статичная читалка на Vanilla JavaScript и Node.js. Первая версия воспроизводит desktop-макеты из [Figma](https://www.figma.com/design/9jjjVWPHGqUzt9wQxuLIVD/izdt): книжная типографика, гравюра, бумажный шум, оглавление, цитаты и цветочная закладка.

## Запуск

Нужен Node.js 22.12+.

### Windows

Распакуйте локальный комплект и дважды нажмите `START-IZDT.cmd`. Он установит зависимости при первом запуске, соберёт сервис и откроет браузер; доступ будет только с этого компьютера. Подробности, резервное копирование и ограничения: [WINDOWS.md](WINDOWS.md).

Тот же режим из терминала на любой ОС: `npm run local`. Шрифты в GitHub отсутствуют, их необходимо добавить отдельно; локальный тестовый комплект для владельца содержит присланные файлы.

### Ручной запуск

```sh
npm ci
npm run build
LOCAL_ONLY=1 TEST_MODE=1 npm start
```

Откройте `http://127.0.0.1:3000`. `TEST_MODE=1` включает редактор без авторизации: использовать только для локального или закрытого тестирования.

Для защищённого запуска:

```sh
EDITOR_TOKEN='your-long-random-secret' npm start
```

Без `TEST_MODE=1` и без `EDITOR_TOKEN` запись книги, оглавления и загрузка изображений запрещены. При первом сохранении интерфейс спросит ключ; он хранится только в памяти вкладки, не в localStorage. За reverse proxy обязательны HTTPS и ограничения доступа. Не помещайте ключ в Git, HTML или URL.

`PORT` (по умолчанию 3000), `HOST` (по умолчанию 127.0.0.1) и `DATA_DIR` задаются окружением. `DATA_DIR` указывает на папку конкретной книги.

`LOCAL_ONLY=1` принудительно ограничивает сервер адресом 127.0.0.1 и проверяет локальные Origin/Host. Лаунчер `npm run local` всегда включает этот режим, использует встроенную книгу и выбирает порт через `IZDT_PORT` (по умолчанию 3000).

## Возможности

- Чтение готового HTML без SPA-фреймворка; основной текст доступен даже без JavaScript.
- E / У: редактор; Esc: сохранить и выйти. Автосохранение и Ctrl+S, проверка версии при конкурентном редактировании, история HTML перед записью.
- Стили H1/H2/H3, основной и малый текст, параграф для оглавления; курсив Ctrl+I, выделение, выравнивание, размер/интерлиньяж/красная строка в rem.
- Вставка PNG/JPEG/WebP/GIF из буфера, файла или drag-and-drop. Сохранение в `img/`; режимы обтекания слева, справа, в строке, сверху/снизу.
- C / С: автоматически составленное оглавление H2 → H3 → параграф. Ручное название, скрытие и индивидуальный сброс хранятся отдельно и не стираются при редактировании.
- Выделение текста → «В заметки». Цитаты подсвечиваются жёлтым и группируются по части/главе; B / И открывает панель.
- Заметки поддерживают несколько абзацев, пересекающиеся выделения и inline-форматирование. При изменении текста уникальная цитата перепривязывается; неоднозначная/удалённая остаётся в заметках с предупреждением.
- Одна перемещаемая закладка в localStorage. Нажатие на ленту возвращает к месту и убирает её с анимацией вверх-вправо.
- Панель сдвигает книгу вправо, не меняя ширину набора. Светлая бумага по макету, дополнительный тёмный режим и reduced-motion.

## Файлы вместо базы данных

```text
data/books/bees/
  content.html           # Текстовая UTF-8-разметка книги
  meta.json              # Название и текущая revision
  toc.json               # Сгенерированное оглавление
  toc-overrides.json      # Ручные правки по стабильным ID
  img/                   # Иллюстрации
  generated/index.html   # Готовый HTML для чтения без личных заметок
  history/               # Предыдущие версии content.html
  readers/<uuid>/
    notes.json           # Цитаты читателя
    index.html           # Сгенерированный HTML с подсветкой
```

Формат содержания: обычный текстовый HTML-файл, не бинарный документ и не БД. Разметка необходима для сохранения стилей, картинок и якорей. Сервер санитизирует HTML, обновляет оглавление и собирает статичную страницу после записи. При сохранении заметки заново собирается личный HTML, общий текст не переписывается.

UUID читателя хранится в localStorage и работает как случайный ключ доступа к его заметкам, не как полноценная учётная запись. Синхронизации между устройствами и восстановления после очистки браузера пока нет. При запрете localStorage интерфейс предупреждает и держит идентификатор только до закрытия вкладки. Личные файлы не раздаются напрямую статическим сервером.

Записи в процессе сериализованы, каждый файл заменяется атомарно через rename. Несколько связанных файлов не образуют транзакцию файловой системы: для production нужны резервное копирование и более строгий журнал восстановления при аварийном выключении. Запускайте один Node-процесс на каталог данных.

## Структура кода

```text
server/
  index.js       # HTTP, API, ограничения, защищённые операции записи
  store.js       # Файлы, ревизии, история и генерация страниц
  document.js    # Санитизация, нормализация ID и подсветка цитат
  template.js    # Статичный HTML-скелет
shared/model.js  # Формат данных и алгоритм оглавления
public/js/
  app.js         # Сборка интерфейса и горячие клавиши
  api.js         # HTTP, состояние читателя и безопасный localStorage
  editor.js      # contenteditable, форматирование и автосохранение
  panels.js      # Оглавление и заметки
  notes.js       # Привязка выделений
  bookmark.js    # Лента и localStorage
```

Две runtime-зависимости: `linkedom` для DOM на сервере и `sanitize-html` для безопасной обработки разметки. Lucide используется только при сборке: SVG копируются в статические assets. Браузер не загружает framework или иконки с CDN.

Редактор использует нативный contenteditable/execCommand для базовых операций и undo/redo. Это MVP-решение с известными ограничениями браузерного редактирования; для сложной вёрстки следующих версий следует заменить его собственными транзакциями над документом, не меняя файловое хранилище.

## Макеты, шрифты и контент

- Исходный дизайн и графика: [Figma izdt](https://www.figma.com/design/9jjjVWPHGqUzt9wQxuLIVD/izdt).
- Шрифты не коммитятся. Имена файлов и условия тестового подключения описаны в `public/fonts/README.md`.
- Присланные Marxiana Trial предназначены для тестирования, не для production. Лицензии и полноценные web-файлы требуются до публичного запуска.
- В репозитории только фрагмент книги из макета, не полная оцифровка издания. OCR-ошибки в этом фрагменте частично исправлены; редакторская сверка с оригиналом ещё нужна.
- Мобильная версия намеренно не реализована: минимальная ширина desktop-раскладки 900 px.
- Статус «production-ready» не заявляется. До публичного запуска нужны полноценные учётные записи/сессии, rate limiting, квоты файлов, резервное копирование, журнал восстановления и права на шрифты.

## Сборка и проверки

```sh
npm test
npm audit
npm run build
```

Браузерные проверки запускаются на работающем тестовом сервере с портом 3000:

```sh
npx playwright install chromium
node scripts/qa-browser.js
node scripts/qa-editor.js
```

Эти проверки временно редактируют тестовую книгу и восстанавливают исходный текст в `finally`. Запускать только на отдельной тестовой копии, не на рабочем издании. Скриншоты записываются в `.qa-output/`, не попадающую в Git.

`dist/` содержит статичную копию для предпросмотра. Для редактирования требуется запущенный сервер. Параметр `PREVIEW_API_BASE` связывает статичную сборку с backend; в обычном развёртывании API и файлы обслуживаются с одного origin.

```sh
PREVIEW_API_BASE=__PORT_3000__ npm run build
```

В приватном предпросмотре Computer адрес заменяется на прокси sandbox-сервера. Production-сервер разворачивается отдельно; preview не является постоянным хостингом данных.
